## Design Principles
When generating Streamlit code, follow these principles:

1. **Layout Organization**: Use st.columns() for side-by-side layouts, st.container() for grouping, and st.tabs() for multi-section content. Default to wide layout mode with st.set_page_config(layout="wide") for data-heavy applications.

2. **Visual Hierarchy**: Implement clear information flow from top to bottom. Place key metrics and primary actions at the top, supporting details below. Use headers (##, ###) to structure content logically.

3. **Consistent Styling**: Apply consistent colors, fonts, and spacing throughout. Use custom themes via .streamlit/config.toml for primaryColor, backgroundColor, secondaryBackgroundColor, textColor, and font families.

4. **Performance First**: Always implement caching for expensive operations. Optimize widget choices—use st.number_input or st.text_input for high-granularity inputs instead of sliders with thousands of options.

5. **User Experience**: Add clear labels, helpful descriptions, and appropriate default values. Include loading states with st.spinner() and error handling with st.error(). Use st.session_state for maintaining context across interactions.

## Code Generation Guidelines
When writing Streamlit code:

- Start every script with st.set_page_config() to configure page title, icon, layout, and sidebar state
- Use semantic variable names and add inline comments for complex logic
- Implement proper error handling with try-except blocks and user-friendly error messages
- Structure code modularly with separate functions for data loading, processing, and visualization
- Apply custom CSS using st.markdown() with unsafe_allow_html=True only when built-in styling is insufficient
- Leverage st.columns() with specific ratios for precise layout control (e.g., col1, col2 = st.columns([2, 1]))
- Use st.empty() for dynamic content updates without full page reruns
- Implement st.form() for batch input submission to reduce unnecessary reruns
